# Сервис искусственного интеллекта по оценке качества исследований плотности костей человека (DXA)

Данный репозиторий содержит production-ready решение для автоматизированного контроля качества рентгеновских денситометрических исследований (DXA). Проект реализован в виде микросервиса на базе **FastAPI**, оптимизирован для пакетной обработки DICOM-файлов и поддерживает аппаратное ускорение на GPU (NVIDIA CUDA).

## 1. Назначение, основные возможности и ограничения

**Назначение:** Автоматизация контроля качества снимков поясничного отдела позвоночника и проксимального отдела бедра. Сервис выявляет артефакты, нарушения позиционирования и укладки, формируя структурированный отчет и визуализацию ошибок для врача.

**Основные возможности (Features):**

* **FastAPI Backend:** Готовый REST API для высокоскоростной пакетной обработки.
* **Умная маршрутизация:** Автоматическое определение анатомической области (Spine/Hip) на основе разметки или эвристики пропорций матрицы снимка.
* **Продвинутая предобработка:** Динамический выбор кадра с наивысшим контрастом (для многокадровых DICOM), нормализация по перцентилям, коррекция фотометрической интерпретации.
* **Оптимизация инференса:** Использование **Test-Time Augmentation (TTA)** и **Mixed Precision (FP16/bfloat16)** для максимизации метрик ROC AUC и скорости работы на современных GPU.
* **Explainable AI (Grad-CAM):** Автоматическая генерация тепловых карт для бракованных снимков с подсветкой локализации артефактов (сохраняется в ZIP-архив).
* **Отказоустойчивость:** Защита от падений на «битых» DICOM-файлах — ошибки перехватываются и логируются в итоговом отчете.

**Ограничения:**

* Определение правила геометрических отступов («3 см / 2 см») в данной версии реализовано математически через расчет физического размера пикселя (PixelSpacing/ExposedArea). Для полной визуальной проверки требуется интеграция модели детекции bounding box (YOLO), под которую в коде зарезервирован метод `check_geometry_rules`.

**Ключевые Python-зависимости (см. `requirements.txt`):**

## 4. Сборка и запуск контейнеризированного приложения

### Запуск на сервере с NVIDIA GPU (Рекомендуется)

1. Убедитесь, что в файле `docker-compose.yml` раскомментирован блок `deploy` с резервированием GPU.
2. В терминале выполните сборку и запуск в фоновом режиме:

```bash
docker-compose up --build -d
```

### Запуск на локальном ПК (CPU / macOS)

1. Откройте `docker-compose.yml` и закомментируйте блок `deploy` в самом низу файла.
2. Выполните команду:

```bash
docker-compose up --build
```

После успешного запуска документация API (Swagger UI) будет доступна в браузере по адресу: **`http://localhost:8000/docs`**

## 5. Описание реализованного API

Сервис предоставляет один основной эндпоинт для пакетной обработки данных.

* **URL:** `/api/v1/process_batch`
* **Метод:** `POST`
* **Content-Type:** `application/json`

**Пример тела запроса (Request Body):**

```json
{
  "input_folder": "/app/dataset",
  "output_csv": "/app/output/final_submission.csv",

*(Где пути указываются относительно внутренней файловой системы контейнера Docker).*

  "csv_saved_at": "/app/output/final_submission.csv",
  "zip_saved_at": "/app/output/heatmaps_archive.zip",

```

## 6. Формат входных и выходных данных

**Входные данные:**

* Директория, содержащая файлы формата `.dcm` (допускается наличие подпапок).
* (Опционально) Таблица Excel (`.xlsx`) с разметкой для точной маршрутизации исследований.

**Выходные данные:**

1. **CSV-файл:** Отчет, разделенный точкой с запятой (`;`). Строго содержит следующие столбцы:

   * `path_to_study` (String)
   * `study_uid` (String)
   * `image_uid` (String)
   * `anatomical_region` (String: `spine`, `hip`, `unknown`)
   * `quality_class` (Integer: `0` - норма, `1` - нарушение)
   * `violation_type` (String)
   * `processing_status` (String)
   * `time_of_processing` (Float, секунды)

2. **ZIP-архив (`heatmaps_archive.zip`):** Содержит JPEG-изображения с наложенными тепловыми картами (Grad-CAM) для всех снимков, классифицированных как брак (1). Имена файлов уникальны и привязаны к `image_uid`.

## 7. Модели, предобработка и постобработка

**Предобработка (Preprocessing):**

* Извлечение пиксельного массива и динамический выбор наилучшего кадра по дисперсии (для 3D матриц).
* Инверсия цветов на основе тега `PhotometricInterpretation` (MONOCHROME1 -> MONOCHROME2).
* Нормализация интенсивностей (отсечение шумов детекторов по 1-му и 99-му перцентилям).
* Масштабирование (Resize) до $224 \times 224$, конвертация в 3-канальный тензор и стандартизация ImageNet.
* Калькуляция физического размера пикселя (PixelSpacing / ImagerPixelSpacing / ExposedArea).

**Архитектура моделей:**

* Ансамбль из 4-х моделей на базе модифицированной архитектуры **ResNet-18** (binary classification head).
* Модели разделены на роутинг (качество позвоночника, качество бедра) и типизацию (артефакты позвоночника, ротация бедра).

**Постобработка (Postprocessing):**

* **TTA (Test-Time Augmentation):** Усреднение предсказаний (logits) между оригинальным тензором и его горизонтально отраженной копией (`hflip`) для повышения устойчивости.
* **Генерация Grad-CAM:** Извлечение карт активации из слоя `layer4` сети ResNet18, наложение цветовой карты `COLORMAP_JET` на оригинальный рентгеновский снимок.

## 8. Известные ошибки и способы их обработки

1. **Поврежденные или пустые DICOM-файлы:**

   * **Симптом:** Библиотека `pydicom` не может прочитать файл или массив пикселей отсутствует.
   * **Обработка:** Перехватывается на уровне `Dataset`. Файлу присваивается статус невалидного. Сервер не падает, а в CSV-отчет записывается статус `Failure: <текст ошибки из pydicom>`.

2. **Отсутствие необходимых тегов метаданных:**

   * **Симптом:** Отсутствуют UID исследования/снимка или теги `Rows`/`Columns`.
   * **Обработка:** В случае отсутствия UID подставляется значение `Unknown`. При отсутствии размерности снимка и отсутствии его в разметке, снимок помечается как `unknown` анатомия и получает статус `Failure: unsupported anatomy dimensions`.

3. **Запуск на CPU без поддержки Float16:**

   * **Симптом:** Ошибка Autocast в PyTorch.
   * **Обработка:** Реализовано динамическое определение устройства. При инференсе на CPU код автоматически переключается с типа `float16` на `bfloat16`, избегая падений среды выполнения.

## 9. Выводы и особенности реализации

Ключевые архитектурные и продуктовые особенности:

* ** Тепловые карты Grad-CAM:**
  Мы избавились от проблемы «черного ящика». Если нейросеть бракует снимок (находит артефакт или нарушение укладки), алгоритм автоматически извлекает карты активации из глубоких слоев ResNet-18 и накладывает цветовую маску на исходный снимок. 
  * *Польза для врача:* Рентгенолог не просто получает статус «Брак», а наглядно видит подсвеченную красным цветом область, которая смутила алгоритм (например, металлическая пуговица, эндопротез или заваленный таз).
  * *Оптимизация:* Карты генерируются **только** для снимков с нарушениями. Это экономит вычислительные ресурсы и время, позволяя сервису с запасом укладываться в строгие временные лимиты (менее 3 минут на пакет).

* ** Максимальная утилизация серверного оборудования (H200):**
  Переход от цикличной обработки снимков к асинхронному API с использованием `torch.utils.data.DataLoader`. Применение батчинга в связке с вычислениями в половинной точности (`torch.autocast FP16/bfloat16`) позволяет обрабатывать десятки снимков параллельно, раскрывая весь потенциал современных тензорных ядер.

* ** Независимость от качества входных данных (Robustness):**
  Медицинские данные часто бывают неполными. Наш пайплайн имеет многоуровневую систему предохранителей (Fallbacks):
  * Нет `StudyInstanceUID`? Снимок не упадет, а получит временный ID.
  * Нет файла с разметкой `xlsx`? Алгоритм динамически рассчитает пропорции матрицы (Rows/Columns) и сам поймет, позвоночник это или бедро.
  * Файл физически поврежден? `DataLoader` перехватит ошибку, запишет её в CSV-отчет и бесшовно продолжит работу над остальным батчем.

**Заключение:** 
Представленный микросервис успешно решает задачу первичного аудита рентгеновских денситометрических исследований. Благодаря использованию TTA, продвинутой аугментации при инференсе и визуализации ошибок, решение обеспечивает высокую точность и прозрачность для конечного пользователя (врача-рентгенолога).
